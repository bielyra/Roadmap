Lógica & Matemática

Não é preciso ser matemático, mas alguns fundamentos são indispensáveis. A boa notícia: você aprende o que precisa enquanto programa, não em abstrato.

Lógica proposicional e booleana

E, OU, NÃO, XOR. Tabelas-verdade. Leis de De Morgan. São a base de toda condicional e toda estrutura de controle que você escreve. Também essenciais para entender operações bit a bit.

Boolean algebraBitwise opsDe Morgan

Matemática discreta

Conjuntos, relações, combinatória, indução matemática. Aplicada diretamente em análise de algoritmos, criptografia e banco de dados relacional. É a matemática da computação.

ConjuntosCombinatóriaInduçãoPermutações

Teoria dos grafos

Vértices, arestas, grau, conectividade, planaridade. O modelo matemático que está por trás de redes sociais, sistemas de rotas, compiladores e banco de dados relacionais.

GrafosÁrvoresFluxo

Probabilidade e estatística básica

Média, mediana, desvio padrão, distribuições. Imprescindível se você for trabalhar com dados, machine learning ou até análise de performance de sistemas. Também essencial para entender testes A/B.

🔥 EstatísticaDistribuiçõesBayes

Álgebra linear (se for para dados/IA)

Vetores, matrizes e transformações. Só aprofunde se seu caminho for machine learning, visão computacional ou computação gráfica. Caso contrário, noções básicas bastam.

MatrizesVetoresProduto internoEigenvalues

Sistemas Operacionais

Entender o que acontece "abaixo" do seu código é o que te permite escrever software eficiente, fazer debug de problemas difíceis e conversar com engenheiros de infraestrutura.

Processos e threads

A diferença entre processo e thread, o ciclo de vida de um processo, escalonamento de CPU. Fundamental para entender performance, paralelismo e por que seu servidor trava com N conexões simultâneas.

🔥 ThreadsSchedulingContext switch

Concorrência e sincronização

Race conditions, deadlocks, mutexes e semáforos. Se você escreve qualquer código assíncrono ou multi-threaded, esses conceitos são essenciais para não criar bugs impossíveis de reproduzir.

🔥 Mutex / LockDeadlockSemaphoreRace condition

Gerenciamento de memória

Stack vs. heap, alocação dinâmica, paginação e memória virtual. Entender por que um processo consome mais memória do que deveria começa aqui. Garbage collectors e memory leaks fazem sentido depois desse estudo.

Heap / StackPaginaçãoVirtual memoryGC

Sistema de arquivos e I/O

Como arquivos são organizados em disco, buffering de I/O, chamadas de sistema (syscalls). Essencial para quem trabalha com processamento de dados, logs ou qualquer coisa que leia/escreva em disco com frequência.

FilesystemSyscallsBufferinginode

Linux e linha de comando

Praticamente todo servidor roda Linux. Saber navegar no terminal, usar pipes, permissões, processos em background e variáveis de ambiente é habilidade esperada de qualquer dev backend ou DevOps.

🔥 Linux CLIbash/zshchmodps / topgrep / awk

Redes de Computadores

Todo software moderno é distribuído. Entender como dados trafegam pela rede é indispensável para qualquer dev que constrói APIs, trabalha com microsserviços ou faz debug de latência.

Modelo OSI e TCP/IP

As camadas da comunicação em rede. Você não precisa memorizar todas as 7 camadas do OSI, mas entender as camadas de transporte, rede e aplicação é essencial para qualquer dev que trabalha com APIs e servidores.

TCP/IPUDPModelo OSI

HTTP/HTTPS e REST

Como a web funciona: métodos (GET, POST, PUT, DELETE), cabeçalhos, status codes, cookies, sessões. TLS/SSL e por que HTTPS importa. REST é o estilo arquitetural mais cobrado no mercado para APIs.

🔥 HTTP/HTTPS🔥 RESTStatus codesHeadersTLS

DNS, IP e roteamento

Como um domínio vira um IP, o que é um resolver, TTL e propagação de DNS. Saber isso evita horas de debug em problemas de infraestrutura que parecem mágica negra para quem não conhece o mecanismo.

DNSIP / SubnetRoteamentoCDN

WebSockets e comunicação em tempo real

Quando HTTP não é suficiente: conexões persistentes, Server-Sent Events e WebSockets. Cobrado em projetos de chat, dashboards em tempo real, jogos online e notificações push.

🔥 WebSocketSSELong polling

gRPC e GraphQL

Alternativas ao REST em cenários específicos. gRPC é amplamente usado em comunicação entre microsserviços (Google, Netflix). GraphQL é popular em APIs de frontend (GitHub, Shopify, Meta).

🔥 gRPC🔥 GraphQLProtobuf

Banco de Dados

Dados são o ativo mais valioso de qualquer sistema. Saber modelar, consultar e otimizar bancos de dados é uma das habilidades mais cobradas no mercado — independente da stack.

SQL fundamental

SELECT, JOIN (inner, left, right, full), GROUP BY, HAVING, subconsultas, CTEs e window functions. SQL é a habilidade de banco de dados mais cobrada em entrevistas, disparado. Pratique muito.

🔥 SQLJOINsCTEsWindow functions

Modelagem relacional

Entidades, atributos, relacionamentos e normalização (1NF, 2NF, 3NF). Um banco mal modelado é fonte de problemas eternos. Aprenda a fazer um bom diagrama ER antes de criar qualquer tabela.

NormalizaçãoDiagrama ERChave primária/estrangeira

Índices e performance

Como um índice funciona internamente (B-Tree), quando criar e quando evitar, e como usar EXPLAIN/ANALYZE para diagnosticar queries lentas. Habilidade extremamente valorizada e raramente ensinada em cursos básicos.

🔥 ÍndicesEXPLAINQuery planningB-Tree

Transações e ACID

Atomicidade, consistência, isolamento e durabilidade. Entender transações é fundamental para não perder dados em casos de falha ou concorrência. Aprenda sobre níveis de isolamento e problemas como dirty reads.

ACIDTransaçõesIsolation levelsLocks

Bancos NoSQL

Quando e por que usar bancos não-relacionais: MongoDB (documentos), Redis (cache e chave-valor), Cassandra (alta escala), Elasticsearch (busca full-text). Não é "SQL vs. NoSQL" — é a ferramenta certa para cada problema.

🔥 Redis🔥 MongoDBElasticsearchCassandra

📚 Livro

Designing Data-Intensive Applications

Martin Kleppmann — o melhor livro sobre bancos e sistemas de dados modernos. Leitura obrigatória para seniors.

🛠️ Tecnologias

PostgreSQL + Redis

PostgreSQL é o banco relacional open-source mais sofisticado. Redis é onipresente para cache. Domine os dois.

🎓 Plataforma

SQLZoo + Mode Analytics SQL

Pratique SQL com exercícios progressivos e dados reais. Gratuitos e muito eficazes.

🎓 Curso

CMU 15-445 Database Systems

Andy Pavlo — aulas no YouTube. O curso universitário mais completo sobre internals de banco de dados.

📈 Mercado de trabalho

PostgreSQL e MySQL dominam os relacionais. Redis é quase universal para cache. MongoDB e Elasticsearch aparecem em muitas vagas de backend. Saber escrever queries SQL complexas e otimizadas é diferencial imediato em entrevistas.

Paradigmas de Programação

Cada paradigma é uma forma diferente de pensar sobre problemas. Quem conhece mais de um paradigma resolve problemas com mais ferramentas mentais disponíveis.

Orientação a Objetos (POO)

Classes, objetos, herança, polimorfismo, encapsulamento. É o paradigma dominante em Java, Python, C# e Kotlin. Aprenda seus princípios, mas também seus limites — abuso de herança é um dos erros mais comuns.

🔥 POOHerançaPolimorfismoEncapsulamento

Programação funcional

Funções puras, imutabilidade, composição, map/filter/reduce. Presente em JavaScript moderno, Python, Kotlin, Scala e Rust. Ajuda a escrever código mais previsível, testável e livre de efeitos colaterais.

🔥 FuncionalImutabilidadeHigher-order functionsClosures

Programação reativa e assíncrona

Callbacks, Promises, async/await, Observables. Essencial para JavaScript/Node.js, Kotlin Coroutines e qualquer sistema que lida com I/O intenso. É o que permite servidores atenderem milhares de conexões simultâneas.

🔥 Async/AwaitPromisesObservablesEvent loop

Design Patterns (GoF)

Padrões clássicos como Singleton, Factory, Observer, Strategy, Repository. São soluções reutilizáveis para problemas comuns de design. Entenda cada um pelo problema que resolve, não pela implementação decorada.

Design PatternsStrategyObserverFactoryRepository

Complexidade de Algoritmos

A habilidade de analisar "quão rápido" e "quanto memória" um algoritmo consome. Saber Big O permite prever o comportamento do seu código antes de ele ir para produção com milhões de usuários.

Notação Big O, Ω e Θ

O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ). Aprenda a identificar a complexidade de um algoritmo lendo o código — loops aninhados, recursão e chamadas de função trazem pistas claras.

🔥 Big OO(log n)O(n²)Análise amortizada

Complexidade de espaço

Não é só velocidade — memória também tem custo. Recursão profunda usa pilha de chamada. Memoização troca tempo por espaço. Entender esse tradeoff é fundamental para escolher a abordagem certa.

Space complexityCall stackTrade-offs

Análise de algoritmos recursivos (Teorema Mestre)

Como calcular a complexidade de algoritmos recursivos como MergeSort e QuickSort. O Teorema Mestre dá uma fórmula direta para recorrências do tipo T(n) = aT(n/b) + f(n).

Teorema mestreRecursãoRecorrências

Benchmarking e profiling

Teoria e prática precisam se encontrar. Use ferramentas de profiling (cProfile, async-profiler, perf) para medir o que realmente está lento em produção. "Premature optimization is the root of all evil" — mas otimize quando necessário.

🔥 ProfilingBenchmarkingFlame graphs

Testes de Software

Quem sabe testar bem entrega código com muito mais confiança e velocidade no longo prazo. É uma habilidade raramente ensinada nas grades curriculares e extremamente valorizada em equipes maduras.

Testes unitários

Testam uma única unidade de código isolada. Aprenda a escrever testes que são rápidos, determinísticos e fáceis de ler. Princípio AAA: Arrange, Act, Assert. Ferramentas: JUnit (Java), pytest (Python), Jest (JS).

🔥 pytest🔥 JestJUnitAAA pattern

Mocks, stubs e fakes

Como isolar dependências externas (banco de dados, APIs, serviços de e-mail) durante os testes. Entender a diferença entre mock, stub e spy evita testes frágeis que quebram quando a implementação muda.

MockingTest doublesDependency injection

TDD — Test-Driven Development

Escreva o teste antes do código: Red → Green → Refactor. TDD não é sobre ter 100% de cobertura; é sobre usar testes para guiar o design. Muda profundamente como você estrutura código.

TDDRed-Green-RefactorBDD

Testes de integração e E2E

Testam a colaboração entre múltiplos componentes. Playwright e Cypress dominam testes E2E de frontend. Testcontainers é referência para testes de integração com banco de dados real em containers.

🔥 PlaywrightCypressTestcontainersE2E

Cobertura de código e qualidade

Métricas como cobertura de linhas, branches e mutação. Não busque 100% — busque testar os caminhos críticos e os casos de borda. Ferramentas: JaCoCo, Coverage.py, Istanbul.

Code coverageMutation testingSonarQube

📚 Livro essencial

📚 Livro

Clean Code & SOLID

Código é lido muito mais vezes do que é escrito. Clareza, simplicidade e bom design são habilidades que diferenciam devs bons de devs excepcionais — e que chefes e pares sempre percebem.

Nomes, funções e comentários

Nomes que revelam intenção, funções que fazem uma coisa só, comentários que explicam o porquê (não o quê). Parece simples — e transforma a manutenibilidade do código completamente.

NamingSingle responsibilitySelf-documenting code

Princípios SOLID

Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion. São princípios de design orientado a objetos que guiam estruturas mais flexíveis e menos frágeis. Aprenda cada um com exemplos reais de violação.

🔥 SOLIDSRPOCPDIP

Refatoração

Melhorar o design do código sem mudar seu comportamento externo. Reconhecer code smells (código duplicado, função longa, classe inchada) e aplicar os refactorings do catálogo de Fowler. Testes são o pré-requisito da refatoração segura.

RefactoringCode smellsDRYYAGNI

Code review e revisão de pares

Receber e dar feedback construtivo sobre código é uma habilidade social e técnica. Aprenda a revisar código com empatia, apontando problemas e sugerindo alternativas. Ferramentas: GitHub Pull Requests, GitLab MR, Gerrit.

🔥 Code reviewPull RequestsPair programming

Controle de Versão com Git

Git é a ferramenta universal de colaboração em software. A maioria aprende só o básico — dominar Git de verdade evita acidentes graves e facilita muito o trabalho em equipe.

Fundamentos: commits, branches e merges

Commits atômicos e com mensagens claras, criação de branches para features, estratégias de merge. Convenção de commits (Conventional Commits) está cada vez mais adotada para automação de changelogs e semver.

🔥 Git flowConventional commitsMerge vs. rebase

Rebase interativo e histórico limpo

git rebase -i para reorganizar, squash e editar commits. Um histórico limpo é um presente para seus colegas e para você mesmo no futuro. Entenda a diferença entre rebase e merge e quando usar cada um.

Rebase interativoSquashCherry-pickgit bisect

GitHub / GitLab e Pull Requests

Criar PRs descritivos, revisar código de pares, usar issues e milestones, configurar branch protection rules. GitHub Actions para CI/CD básico. Essas plataformas são o ambiente de trabalho real de qualquer dev hoje.

🔥 GitHub ActionsCI/CDBranch protection

Internals do Git (como funciona por dentro)

Objetos blob, tree, commit e tag. SHA-1 e o modelo de conteúdo endereçado. Entender como o Git armazena dados desmistifica completamente seus comandos e elimina o medo de usar operações "destrutivas".

Git objectsDAGReflog

Segurança de Software

Segurança não é uma feature adicional — é uma responsabilidade de todo desenvolvedor. Brechas clássicas existem há décadas porque devs não aprenderam a evitá-las.

OWASP Top 10

As 10 vulnerabilidades mais críticas de aplicações web: SQL Injection, XSS, CSRF, SSRF, Broken Authentication, entre outras. Entender cada uma, como ocorre e como prevenir é conhecimento básico esperado de todo dev backend e fullstack.

🔥 OWASP Top 10SQL InjectionXSSCSRF

Autenticação e autorização

JWT, OAuth 2.0, OpenID Connect. Diferença entre autenticação (quem é você?) e autorização (o que você pode fazer?). Hashing seguro de senhas com bcrypt ou Argon2. Sessões vs. tokens stateless.

🔥 JWT🔥 OAuth 2.0bcryptRBAC

Criptografia aplicada

Não é necessário implementar algoritmos — mas entender quando usar criptografia simétrica (AES) vs. assimétrica (RSA/ECC), o que é hashing (SHA-256) e como TLS protege conexões é fundamental para tomar decisões corretas.

TLS/SSLAESRSA / ECCHashing

Segurança em containers e cloud

Segredos em variáveis de ambiente, IAM roles com least privilege, escaneamento de imagens Docker (Trivy, Snyk), secrets managers (AWS Secrets Manager, HashiCorp Vault). Cada vez mais cobrado em vagas DevOps e backend.

🔥 Secrets managementIAMTrivy / SnykVault

🌐 Referência

OWASP.org

Documentação oficial das vulnerabilidades, cheat sheets e guias de prevenção. Recurso gratuito e definitivo.

📚 Livro

The Web Application Hacker's Handbook

Stuttard & Pinto — aprenda segurança do ponto de vista do atacante. Transforma a forma de pensar sobre defesa.

🎓 Plataforma

HackTheBox / TryHackMe

Plataformas práticas de cybersecurity. Comece por TryHackMe (mais acessível) e avance para HackTheBox.

Arquitetura de Software

Como sistemas são estruturados em alto nível. Esse conhecimento começa a ser exigido a partir do nível pleno e é essencial para cargos sênior. Design de sistemas é um tema central em entrevistas de grandes empresas.

Arquitetura em camadas e MVC

O ponto de entrada: separação entre apresentação, lógica de negócio e dados. MVC, MVP, MVVM. Presente em praticamente todo framework web (Rails, Spring, Django, Laravel). Entenda os princípios antes dos frameworks.

🔥 MVCLayered architectureSeparation of concerns

APIs RESTful e contratos

Design de APIs versionadas, idempotência, paginação, filtros, documentação com OpenAPI/Swagger. Uma API bem desenhada é um produto em si — facilita ou dificulta toda a integração com outros sistemas.

🔥 OpenAPI / SwaggerREST best practicesAPI versioning

Microsserviços e arquitetura distribuída

Decomposição por domínio, comunicação síncrona vs. assíncrona, service discovery, circuit breakers. Ferramentas: Docker, Kubernetes, Kafka, RabbitMQ. É o modelo dominante em grandes sistemas — e traz complexidade proporcional.

🔥 Docker🔥 Kubernetes🔥 KafkaCircuit breaker

Cache, filas e mensageria

Redis para cache, RabbitMQ e Kafka para mensageria assíncrona. Padrões como pub/sub, event-driven, CQRS e event sourcing. Fundamentais para sistemas que precisam escalar horizontalmente.

🔥 Redis cacheRabbitMQCQRSEvent-driven

System design — entrevistas e prática

Como projetar sistemas como o Twitter, YouTube, WhatsApp ou Uber. Envolve tradeoffs entre consistência e disponibilidade (CAP theorem), estimativas de capacidade, sharding, CDN e load balancers. Tema central em entrevistas de nível sênior.

🔥 System designCAP theoremShardingLoad balancer

📚 Livro

🌐 Referência

🛠️ Tecnologias

Docker + Kubernetes + Kafka

As três ferramentas mais cobradas em vagas de backend/platform engineering no mercado atual.

📈 Mercado de trabalho

System design é o tema central das entrevistas técnicas para cargos sênior e staff em qualquer empresa de tecnologia de médio a grande porte. Docker e Kubernetes são exigidos em praticamente toda vaga backend moderna. Kafka aparece em quase todas as vagas de sistemas de alta escala.
